# DAT docs

This is the information for the use of this data analysis template (DAT)
repository for a data analysis projects. The main idea of this repository is to
provide a template structure for the data analysis process. Including useful
templates, shared configuration, folder structure and relevant AI skills.

## Repository structure

The repository is structured around "types of research artifacts" and the
thematic atomic sub-folders within. Each type folder should contain a README
file with more information.

Each atomic folder is (to some extent) self-contained and can run independently.

This does not mean that the input from an atomic folder cannot be used in
another atomic folder. For example, a data analysis atomic folder can use the
output from a data collection atomic folder. However, each atomic folder should
be able to run independently and produce its own output.

The repository contains both code and artifact generation folders.

### Places to store code

The allowed types of code folders are:

- `./src` - for pacakges and libraries that are specifically designed to be used
  in this project.
- `./data` - for atomic folders that aim at producing data. This can include:
  - Self contained nextflow pipelines that produce data from raw data.
  - Data collection scripts that download and process to some minimal level.
  - Runs of externally provided nextflow pipelines that produce data.
- `./analysis` - for atomic folders that aim at producing figures and tables
  from an analysis code.
- `./metadata` - for atomic folders containing metadata about the samples used
  in the project.
- `./sandbox` - for atomic folders that are used for testing and exploring new
  ideas.
- `./models` - for atomic folders that contain machine learning or statistical
  models. The aim being to produce a predictive model, including code and
  training data, not inference or analysis.

### Places to stage research artifacts

The final stage of the process is writting scienctific artifacts.

- `./writting` - for atomic folders related to generating content WITHOUT code,
  such as manuscripts, slides or reports. Each new manuscript, presentation, or
  report should be a new atomic folder. Manuscript templates include an
  `artifacts/` subfolder for pulling local copies of figures, tables, and other
  generated files into that manuscript.

## Template Usage

### Create a new repo from the template

```bash
gh repo create <name> --clone --private --template davidmasp/dat
cd <name>
just template-add-remote
```

`just template-add-remote` defaults to `git@github.com:davidmasp/dat.git`. Pass
a different URL if the template lives somewhere else:

```bash
just template-add-remote git@github.com:org/template-repo.git
```

### Sync template updates

Start from a clean working tree. The sync happens on a temporary branch so
template conflicts can be reviewed before merging into your project branch.

```bash
just template-sync
```

This runs the same workflow as:

```bash
git fetch template
git checkout -b sync/template-updates
git merge template/main --allow-unrelated-histories
```

Resolve any conflicts, commit the merge, test the project, then merge
`sync/template-updates` into your main project branch. Keep your project version
of files when you have intentionally diverged from the template.

### List available templates

```bash
just list-templates
```

Current starter folders include:

- `data_external_pipeline`
- `data_pipeline`
- `data_simple`
- `manuscript_simple`
- `manuscript_typst`
- `sandbox_simple`

### Create project folders from templates

Copy a template into a destination path relative to the repository root:

```bash
just create-from-template <template-name> <destination-path>
```

For example:

```bash
just create-from-template data_simple data/my_data_source
just create-from-template data_pipeline data/my_pipeline
just create-from-template sandbox_simple sandbox/my_exploratory_analysis
just create-from-template manuscript_simple manuscripts/my_manuscript
just create-from-template manuscript_typst manuscripts/my_typst_manuscript
```

After copying, edit placeholders and local settings directly in the copied
folder.

### Gather manuscript artifacts

Manuscript templates include an `artifacts/` subfolder. Configure source files
in `artifacts/input.toml`; each copied artifact writes checksum state to
`artifacts/state.toml`.

```bash
cd writting/my_manuscript/artifacts
just copy
just check
```

### Nextflow configuration

Reusable Nextflow profile snippets live in [`config/nextflow`](config/nextflow),
including local, HPC, Slurm, SGE, conda, micromamba, Apptainer, and Tower
configuration files.
